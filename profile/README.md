## What is Manictime Time Tracking

Manictime Time Tracking is a desktop-based time and activity tracking application that records computer use and helps turn daily work into structured records. ## Workday Evidence Trail

A typical ManicTime day begins when the desktop records the first meaningful computer activity, then organizes detected applications, websites, idle periods, and project labels into a timeline that can be reviewed before reporting.

[![Time tracking workflow badge](https://img.shields.io/badge/Manictime-2563EB?style=flat-square&logo=clockify)](https://charlesreynoldsocnh.github.io/.github/manictime-time-tracking)

1. **Start of day:** The record begins with first activity, clock-in context, or a manually added attendance entry.
2. **Activity capture:** Desktop use, applications, websites, and idle time are grouped into sessions.
3. **Project assignment:** Users classify blocks of time into clients, projects, tasks, or internal categories.
4. **Correction window:** Missing entries, offline periods, and wrongly grouped sessions can be adjusted before submission.
5. **Review stage:** A worker, manager, or billing reviewer checks totals, idle periods, and category accuracy.
6. **Approval or export:** Approved data can support reports, payroll checks, billing exports, or productivity analysis.

## Automation Versus Manual Trust

| Tracking method | Where it increases accuracy | Where it can create noise | What reviewers should verify |
|---|---|---|---|
| Automatic tracking | Captures detailed desktop activity without requiring constant user input | Background activity can be misread if apps remain open but unused | Confirm idle thresholds, app grouping, and category rules |
| Manual timers | Gives users direct control over intentional task timing | Timers can be forgotten, duplicated, or started late | Compare timer entries with timeline evidence |
| Attendance entries | Helps show when a workday starts, pauses, and ends | Attendance alone does not prove focused work | Check consistency with active sessions and approved breaks |
| Integrations | Connects tracked work to projects, billing systems, or reports | Imported data may not match local activity categories | Validate project mapping and export rules |
| Retrospective edits | Allows users to correct meetings, offline work, and missing classifications | Excessive edits can reduce confidence in raw activity records | Review edit history, notes, and approval policy |
| Desktop capture | Makes ManicTime desktop time tracker data useful for detailed work reconstruction | Desktop records may overrepresent computer-based work and underrepresent calls or field work | Confirm whether non-desktop work is documented separately |
| Employee reporting | Optional ManicTime employee monitoring can support oversight when policies are clear | Monitoring can be intrusive if scope and access are unclear | Verify consent, access controls, retention rules, and report purpose |
